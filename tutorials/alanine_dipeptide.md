# Alanine Dipeptide Flow-Matching Tutorial

This tutorial trains an equivariant flow-matching model on Alanine dipeptide,
generates an independent conformational ensemble, and compares the training and
generated ensembles through periodic Ramachandran density estimates.

Run all commands from the GEqDiff repository root.

## 1. Set Up The Environment

Create the virtual environment and install GEqDiff, GEqTrain, PyTorch, and the
analysis dependencies:

```bash
./venv_setup.sh
source .venv-geqdiff/bin/activate
```

Confirm that commands and imports resolve inside this environment:

```bash
which python
which geqtrain-train
python -c "import torch, geqdiff, geqtrain; print(torch.__version__)"
```

Do not prepend a different GEqTrain checkout to `PYTHONPATH`: the source used to
instantiate a checkpoint must be compatible with the source used for training.

## 2. Inspect The Reference Dataset

The tutorial uses `data/train_750.npz`. It contains 750 heavy-atom conformations
of the same ten-atom Alanine dipeptide topology:

- `coords`: coordinates with shape `(750, 10, 3)`.
- `atom_types`: element classes shared by all frames.
- `atom_indices`: fixed identities `0, ..., 9`, shared by all frames.
- `dihedral_idcs`: atom-index quadruplets defining phi and psi.
- `dihedrals`: reference phi/psi values in radians.

Inspect the file directly:

```bash
python - <<'PY'
import numpy as np

with np.load("data/train_750.npz") as data:
    for key in data.files:
        value = data[key]
        print(f"{key:16s} shape={value.shape!s:14s} dtype={value.dtype}")
    print("dihedral atom indices:\n", data["dihedral_idcs"])
PY
```

Plot the reference Ramachandran distribution:

```bash
python geqdiff/scripts/plot_alanine_ramachandran.py \
  --input data/train_750.npz \
  --output results/alanine_reference_ramachandran.png \
  --title "Alanine reference ensemble"
```

The plot uses a wrapped Gaussian kernel-density estimator. Angular differences
are computed periodically, so samples near `-180` and `180` degrees contribute
to the same region. The default bandwidth is 12 degrees; use, for example,
`--bandwidth 8` for a sharper map or `--bandwidth 18` for more smoothing.
Regions farther than three bandwidths from every observation are shown in white,
and contour lines indicate equal-density levels. Adjust this cutoff with
`--support-radius` and select another Matplotlib color map with `--cmap`.

## 3. Understand The Training Configuration

The complete experiment is defined by
`config/alanine/experiment/alanine_flow.yaml`. Hydra composes it with:

- `config/alanine/data/alanine.yaml`: 650 training and 100 validation frames.
- `config/alanine/model/flow_model.yaml`: equivariant interaction model.
- `config/alanine/train/flow.yaml`: loss, optimizer, scheduler, and epochs.

The model receives three node-level inputs:

- `node_types` identifies C, N, and O atoms.
- `node_indices` identifies each atom's fixed position in the ten-atom topology.
- `conditioning` is the flow-time embedding generated by the flow module.

Only coordinates are corrupted. For a clean conformation `x_data`, centered
Gaussian noise `x_noise`, and flow time `tau`, training constructs

```text
x_tau = (1 - tau) * x_data + tau * x_noise
```

and learns the corresponding coordinate velocity. Both molecular coordinates
and coordinate noise are centered per graph, removing arbitrary translation.
The output is an unconstrained `1x1o` vector; it must not be normalized because
velocity magnitude is part of the target.

The latent representation includes angular orders through `l=2`, while the
final readout predicts the `l=1` coordinate velocity. With `parity: o3_full`,
positions and velocities use odd-parity polar vectors.

## 4. Train

Start the same experiment with a tutorial-specific run name:

```bash
geqtrain-train config/alanine/experiment/alanine_flow.yaml \
  -d cuda:0 \
  -o run_name=alanine_tutorial
```

Use `-d cpu` when CUDA is unavailable. Remove the `run_name` override to use the
name stored in the experiment YAML. Training writes the resolved configuration,
log, last checkpoint, and best validation checkpoint under:

```text
results/alanine_tutorial/
```

Monitor progress with:

```bash
tail -f results/alanine_tutorial/log
```

The principal objective is `loss_velocity`. Select `best_model.pth` for sampling
because it corresponds to the lowest configured validation metric, rather than
simply the final epoch.

For a short pipeline check, override the duration without editing the config:

```bash
geqtrain-train config/alanine/experiment/alanine_flow.yaml \
  -d cuda:0 \
  -o run_name=alanine_tutorial_smoke \
  -o max_epochs=5
```

This smoke run verifies execution but is not expected to reproduce the reference
conformational distribution.

## 5. Sample A Generated Ensemble

Sampling uses `data/ala.pdb` as topology and atom-order metadata. The model was
trained on ten heavy atoms, so `--noh` is required. The sampler reads the model
configuration, supplies the same graph-local `node_indices` (`0, ..., 9`) used
during training, and automatically selects flow-matching integration.

Generate 1,000 conformations in manageable batches:

```bash
python geqdiff/scripts/sample.py \
  --model results/alanine_tutorial/best_model.pth \
  --input_structure data/ala.pdb \
  --noh \
  --device cuda:0 \
  --output results/alanine_tutorial/generated \
  --num_samples 1000 \
  --batch_size 64 \
  --steps 20 \
  --seed 13
```

This writes `results/alanine_tutorial/generated.xyz`, with one ten-atom XYZ
frame per generated conformation. Increase `--steps` to test integration
convergence, but more steps cannot compensate for an undertrained velocity
field. Keep the seed fixed when comparing checkpoints or step counts.

For a quick functional test, use `--num_samples 64`; use hundreds or thousands
of samples for a meaningful density comparison.

## 6. Plot The Generated Ramachandran Distribution

Compute phi and psi from the generated coordinates using the exact atom-index
definitions stored in the training dataset:

```bash
python geqdiff/scripts/plot_alanine_ramachandran.py \
  --input results/alanine_tutorial/generated.xyz \
  --dihedral-source data/train_750.npz \
  --output results/alanine_tutorial/generated_ramachandran.png \
  --title "Alanine generated ensemble"
```

Use the same KDE bandwidth for the reference and generated plots. Compare:

- Locations of the major conformational basins.
- Relative probability mass assigned to each basin.
- Spurious density in regions absent from the reference data.
- Mode collapse, visible when a reference basin is missing from generated data.
- Over-dispersion, visible as generated basins that are substantially broader.

The 100 held-out frames configured in `n_val` measure velocity prediction during
training. The generated Ramachandran plot measures a different property: whether
integrating the learned velocity field produces the target conformational
distribution. Low validation loss is necessary but does not by itself guarantee
correct long-horizon sampling.

## 7. Reproduce And Report

For reproducible comparisons, report the following together:

```bash
git rev-parse HEAD
python -c "import torch; print(torch.__version__)"
grep -E "Best model|loss_velocity" results/alanine_tutorial/log | tail -20
```

Archive the resolved `results/alanine_tutorial/config.yaml`, selected checkpoint,
sampling command, random seed, number of generated samples, integration steps,
and KDE bandwidth. These values determine whether two Ramachandran maps are a
controlled comparison.
